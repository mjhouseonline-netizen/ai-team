ROOT CAUSE

Something is overriding the flexbox layout, causing elements to be

- Mobile CSS overrides
- Browser rendering quirks
- Conflicting CSS rules

═══════════════════════════════════════════════════════════════════

NUCLEAR OPTION - FORCEFUL FIX

Added explicit CSS with !important to FORCE correct layout:

```css
/* CRITICAL: Force guest mode layout to work correctly */
body.guest-mode .main-content {
    display: flex !important;
    flex-direction: column !important;
    justify-content: flex-start !important;
    align-content: flex-start !important;
}

body.guest-mode .header {
    order: 1 !important;
    flex-shrink: 0 !important;
}

body.guest-mode .chat-container {
    order: 2 !important;
    flex: 1 !important;
}

body.guest-mode .input-container {
    order: 3 !important;
    flex-shrink: 0 !important;
}
```

This uses:
- !important to override any conflicting rules
- flexbox order property to force correct sequence
- flex-shrink: 0 to prevent header/input from collapsing
- flex: 1 to make chat-container fill space

WHY THIS SHOULD WORK

Using !important + flexbox order is the "nuclear option" - it
overrides almost everything. If this doesn't work, the issue is
likely JavaScript-based or a template rendering problem, not CSS.

The order property in flexbox explicitly controls visual order
regardless of DOM order, so even if something is trying to move
elements around, this should force them into the correct positions.
